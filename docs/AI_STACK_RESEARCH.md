## 1. 조사 배경 및 목적

온담 서비스의 AI 파이프라인 구현 전에 각 기능별 최적 AI API를 선정하기 위해 크롤링 기반 조사를 진행했다.
단순 추정이 아닌 **실제 가격 페이지 크롤링 + Reddit/커뮤니티 반응 조사** 기반으로 정리.

## 2. 사용자 확정 방향 (대화 중 결정된 사항)

| 영역 | 선택 | 근거 |
|------|------|------|
| **이미지 처리 전체** | Gemini | 사용자 선호 ("이미지 관련 전부 다 Gemini로") |
| **영상 생성** | Higgsfield | 사용자 확인 ("광고에서 퀄리티 좋고, 커뮤니티에서도 많이 씀") |
| **음성 복제** | ElevenLabs | 초기부터 확정, 변경 없음 |

### 사용자 제시 AI 파이프라인 (유언장 플로우)

```
[사용자 사진 업로드]
      ↓
[Gemini] → 영정사진 생성 (정장·격식체 스타일)
      ↓
[Gemini] → 일상복 사진 생성 (자연스러운 복장)
      ↓
[ElevenLabs] → 음성 클론 + 유언 텍스트 → 음성 파일
      ↓
[Higgsfield] → 일상복 사진 + 음성 → 말하는 영상 (립싱크)
```

## 3. 영상 생성 AI 조사 결과

### 3-1. Higgsfield (학스필드) - 사용자 선택

| 항목 | 내용 |
|------|------|
| **주 용도** | 시네마틱 숏폼 영상, 소셜 광고 콘텐츠 |
| **API 여부** | 있음 (REST API) |
| **가격** | $149+/월 (API 플랜) |
| **커뮤니티 반응** | 광고 퀄리티 영상에서 호평, 소셜 콘텐츠 제작자 다수 사용 |
| **Lipsync 기능** | 있음 (사진 + 음성 → 말하는 영상) |

**조사에서 확인된 한계점** (참고용, 사용자가 인지하고 선택):
- 긴 영상에서 얼굴 떨림(face drift) 현상 보고 있음
- 주 강점은 시네마틱 영상이며 talking head는 부가 기능
- 시간적 일관성(temporal consistency) 점수: 3.4/10 (타 도구 대비)

## 4. 이미지 처리 AI 조사 결과

### 4-1. Gemini - 사용자 선택

| 기능 | Gemini 가능 여부 | 비고 |
|------|----------------|------|
| 화질 복원 (enhance) | 가능 | Gemini 2.0 Flash 이미지 편집 |
| 흑백→컬러 변환 | 가능 | 프롬프트 기반 컬러화 |
| 오래된 사진 복원 | 가능 | 손상 복원 |
| 배경 제거 | **불가** | 투명 PNG 출력 미지원 |
| 영정사진 생성 (정장 합성) | 조건부 가능 | 얼굴 보존 안정성 문제 보고 있음 |
| 일상복 사진 생성 | 조건부 가능 | 동일 얼굴 보존이 핵심 과제 |
| 반려동물 AI 초상화 | 가능 | 수채화/유화/만화 스타일 |

**조사에서 확인된 Gemini 한계점** (참고용):
- `투명 배경 PNG 출력 불가` - 배경 제거 기능에 직접 사용 불가
- `얼굴 보존(face consistency)` - 복잡한 옷 스타일 변경 시 얼굴이 달라지는 사례 보고
- 정확한 face-swap 수준의 동일인 보장은 어려움

### [결정 1] 배경 제거 (remove-bg) 구현 방법

Gemini는 투명 PNG 출력이 불가능하므로 배경 제거는 별도 처리가 필요합니다.

**옵션 1-A** - `remove.bg API` 유지  
- 투명 PNG 완벽 지원  
- 비용: $0.05/이미지  
- 기존 PRD 계획과 동일  

**옵션 1-B** - `rembg` 오픈소스 Python 서버 자체 운영  
- 무료 (서버 비용만 발생)  
- Python 워커 별도 구축 필요  
- 응답 속도 자체 서버에 의존  

**옵션 1-C** - `Gemini`로 통일 (배경 제거 기능 제외)  
- 배경 제거를 서비스 기능에서 제외하거나 흰 배경 교체 방식으로 대체  
- 구현 가장 단순  

---

### [결정 2] 영정사진 생성 방식

업로드된 사진에서 정장 착용 영정사진을 만드는 방법입니다.

**옵션 2-A** - `Gemini 이미지 편집`만 사용  
- 프롬프트: "이 사람의 얼굴을 유지하면서 정장으로 교체해줘"  
- 비용: Gemini API 비용만  
- 리스크: 얼굴 불일치 발생 가능  

**옵션 2-B** - `FASHN.AI` (가상 착용 특화 API) 사용  
- 얼굴 보존하면서 옷만 교체하는 데 특화  
- 정장 이미지를 별도 준비해서 합성  
- 비용: FASHN.AI API 별도  

**옵션 2-C** - `Gemini` 배경 합성 + `remove.bg` 조합  
- remove.bg로 인물 누끼 → Gemini로 정장 배경 생성 → 합성  
- 두 API 조합  

**옵션 2-D** - 정장 합성 기능 제외, 단순 화질 개선만 제공  
- 서비스 범위를 줄이는 대신 구현 단순화

### [결정 3] Higgsfield 사용 확정 여부

사용자가 Higgsfield를 선택했으나, talking head 용도의 실제 성능을 재확인하는 옵션입니다.

**옵션 3-A** - `Higgsfield` 그대로 진행  
- 사용자 선택 존중  
- 광고 퀄리티 콘텐츠 기준으로는 검증됨  
- face drift 이슈는 영상 길이 제한(30초 이하)으로 완화 가능  

**옵션 3-B** - `SadTalker` (Replicate)  
- talking head 원래 목적으로 만들어진 모델  
- $0.094/run으로 저비용  
- 자체 서버 오픈소스 실행 시 무료  

**옵션 3-C** - `Hedra Character-3`  
- 현재 talking head 최고 품질  
- $75/월 (5분 영상 한도)  
- API 있음  

**옵션 3-D** - `HeyGen`  
- 커뮤니티 1위 퀄리티 평가  
- $29~199/월  
- 서비스 안정성 이슈 있음  

**옵션 3-E** - `D-ID` (기존 PRD 원안)  
- 코드베이스에 이미 TODO로 준비됨  
- 프레임워크 성숙, 안정적  
- $0.05~0.2/분

### [결정 4] 흑백→컬러 및 화질 복원 구현

사진관의 화질 복원·컬러화 기능을 어떻게 구현할지입니다.

**옵션 4-A** - `Gemini`로 통일  
- 화질 복원, 컬러화 모두 Gemini API  
- 단일 API 관리  
- 전문 모델 대비 품질 차이 있을 수 있음  

**옵션 4-B** - 특화 오픈소스 (CodeFormer + DDColor) 자체 서버  
- 화질 복원: CodeFormer (얼굴 특화)  
- 컬러화: DDColor  
- Python 서버 별도 운영 필요, API 비용 없음  
- 품질 우수  

**옵션 4-C** - 혼합: Gemini (기본) + 특화 API (고화질 옵션)  
- 기본 처리: Gemini  
- 고화질 옵션: 특화 API (유료 업그레이드)  
- 서비스 가격 차별화 가능

### [결정 6] 일상복 사진 생성 방식

유언장 영상의 베이스가 되는 "자연스러운 일상복 사진"을 어떻게 만들지입니다.

**옵션 6-A** - `Gemini 이미지 편집`  
- 프롬프트: "이 사람의 일상복 자연스러운 사진으로 만들어줘"  
- 별도 API 없이 Gemini만 사용  
- 얼굴 일관성 리스크 있음  

**옵션 6-B** - 별도 생성 없이 업로드된 원본 사진 그대로 사용  
- 복잡도 없음  
- 사용자가 적합한 사진을 직접 업로드하도록 UX 설계  
- 구현 가장 단순  

**옵션 6-C** - `FASHN.AI` 가상 착용으로 자연스러운 캐주얼 옷 입히기  
- 전문 가상 착용 API  
- 얼굴 보존 강점  
- 별도 API 비용
