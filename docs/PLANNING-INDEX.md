## 2. 현재 상태와 우선순위 (2026-08-23)

### 지금 어디에 있나

- **전제가 바뀌었다: 로컬 실환경이 생겼다.** WSL에 MySQL 8.4 + Redis를 구축하고 `ondam_schema.sql`을 적용(30테이블 에러 0건)한 뒤 **처음으로 애플리케이션을 실제 기동**했다. 마이그레이션 4세트는 전부 스키마 파일에 통합돼 있어 신규 DB는 `ondam_schema.sql` 1회 실행이면 최종 상태다(`docs/migrations/`는 이력용).
- **검증 방식이 3종으로 늘었다**: 정적 분석 + 실제 API 호출(curl) 전 도메인 스모크 + 브라우저 렌더링 확인. **세 가지가 서로를 대체하지 못한다**는 것이 이번 라운드의 결론이다 - 최악의 결함들이 전부 curl 200이었다. 상세: `review/2026-08-23-verification-record.md` 3절
- **이번 라운드 수정**: 동의 검증 체계 전면 정비(출시 차단급), 실사용 차단 결함(필드명 drift·결제 무한정지·무한 폴링·인증 재시도), 보안 노출(벤더 SDK 원문·결제키·내부 식별자), 정합성(AI 실패 시 상태 복원·선물 환불 연쇄), 명칭 전량 교체 + 법적 효력 고지 삽입
- **아직 한 번도 실행되지 않은 영역이 남아 있다** - 벤더 키가 없어 실결제·실환불·실제 AI 처리·알림 도달·카카오 OAuth·웹훅·S3·KMS가 전부 미확인이다(`review/phase0-followups.md` H절). "정상"이 아니라 "미검증"으로 취급한다

### 우선순위

1. **[오너] 도메인 확보** (`ondam.kr`) - **최대 병목.** 토스 웹훅·카카오 Redirect URI·알림톡 링크가 전부 요구한다. 없으면 벤더 심사 신청서 자체를 못 쓴다
2. **[오너] 벤더 계정 발급** - 토스(상점 심사)·D-ID·Gemini·ElevenLabs·알림톡(채널+템플릿 심사)·AWS. 1번이 선행. 이게 풀려야 H절 미검증 영역을 검증할 수 있다
3. **[오너] 법무 초안 검토 발주** - 리드타임 최장. **N-01(동의 철회 수단이 법적 의무인지)이 개발 범위를 바꾼다**
4. **[개발] 동의 관리 화면 + `GET /api/auth/consents`** - E-1. 3번 답에 따라 출시 전 필수가 될 수 있다
5. **[개발] 이번 라운드 잔여 결함** - `voiceWorker` 동의 재검증(E-2), 선물 경로 무한 폴링(E-4)
6. **[개발] 알림톡 어댑터·계측** - 벤더/도구 선정 후 (E-6·E-7)

## 5. 문서 관리 규칙

- **카피·명칭**은 `strategy/11-brand-messaging`이 SSOT. 다른 문서와 어긋나면 11을 따른다.
- **개발 태스크**는 `strategy/06-dev-backlog`이 SSOT (DEV 번호).
- **기능 동작 정책**은 해당 `specs/SPEC-*`가 SSOT. PRD와 충돌 시 SPEC 우선.
- **재발 방지 규약**은 `guidelines/DEVELOPMENT_GUIDELINES.md`(G1~G15)가 SSOT다. 새 규칙은 기존 번호 뒤에 이어 붙이고 기존 항목을 덮어쓰지 않는다.
- **검토 라운드 기록**은 `review/`에 `YYYY-MM-DD-*.md`로 새 파일을 만든다. 이전 리포트를 고쳐 쓰지 않는다 - 어느 시점에 무엇을 알고 있었는지가 남아야 한다. 후속 태스크는 `review/phase0-followups.md`에 절을 추가한다.
- 결정이 바뀌면 해당 SSOT 문서부터 고치고, 이 인덱스의 3·4절 상태를 갱신한다.
- 충돌은 숨기지 말고 표면화한다(SPEC-00 통제 원칙).
