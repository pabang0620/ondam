# 온담 출시 체크리스트

> 작성 배경: `strategy/05-execution-phases.md`가 Phase 게이트(무엇이 끝나야 다음으로 가는가)를 정의하지만, **"출시 당일 무엇을 하나씩 확인하는가"**가 없었다. 게이트는 판정 기준이고 이 문서는 실행 목록이다.
>
> **대상**: Phase 2(AI 사진관 단독 출시)를 1차 기준으로 작성했다. Phase 3(마지막 영상 편지 출시) 때는 영상 편지 관련 항목이 추가로 활성화된다. 항목 옆 `[영상편지]` 태그가 그것이다.
>
> **사용법**: 이 파일을 복사해 출시 회차별로 체크한다. 원본은 비워둔 채 유지한다.
> **원칙**: 체크되지 않은 항목이 하나라도 "필수"에 남아 있으면 출시하지 않는다. "출시하고 고치자"는 결제·전달이 걸린 이 서비스에 적용하지 않는다.

- [ ] 모바일 실기기 확인 (5060 주 사용 환경)
- [ ] 사용자 노출 문구에 em-dash 사용 0건 (하이픈만 사용, 11 문서 5절)

## 8. 초기 안전장치

> 1인 운영에서 첫날 주문이 몰리면 **수동 검수와 CS가 먼저 무너진다.** 서버보다 사람이 병목이다.

- [ ] **첫날 주문 상한 검토** - 결정 사항: 상한을 둘지, 둔다면 몇 건인지, 어떻게 거는지(광고비 상한 / 노출 제한 / 하드 상한)
  - 권고: 하드 상한보다 **광고·노출을 조여 유입 자체를 조절**하는 편이 낫다. 주문을 거절당한 경험이 5060에게 남기는 인상이 나쁘다
- [ ] `[영상편지]` 사후 공개 검수 대기가 하루 5건을 넘으면 2인째를 붙인다는 기준 합의 (CS_PLAYBOOK 5-2)
- [ ] **롤백 절차 숙지** (OPERATIONS 3-4)
  - [ ] 앱만 롤백하고 스키마는 두는 것이 기본이라는 점 확인
  - [ ] 롤백 실행 명령을 미리 적어두고 손에 익혀 둠
- [ ] **장애 시 연락 체계** - 누가 누구에게 어떤 순서로 연락하는가. 1인이면 "무엇을 먼저 멈추는가"를 정해둔다
  - [ ] 최우선 중단 대상: 사후 공개 승인 (오전달이 최고 심각도)
  - [ ] 그다음: 신규 결제 접수
- [ ] 점검 공지 문안 준비 (무중단 배포가 아니면 필요)
- [ ] `PAYMENT_MOCK`은 어떤 장애 상황에서도 켜지 않는다는 점 재확인

## 9. 출시 후 24시간 모니터링

> 시각을 정해두고 본다. 권장: 출시 후 1시간·3시간·6시간·12시간·24시간.

| 시점 | 확인 항목 |
|---|---|
| 매 확인 | 5xx 발생 건수 |
| 매 확인 | AI 작업 최종 실패 건수 (실패는 곧 자동 환불 = 원가 누수 + CS) |
| 매 확인 | 결제 실패 건수 / **`pending`·불확정 잔존 건** (1건이라도 사람이 확인) |
| 매 확인 | 큐 적체 (대기 건수가 계속 늘고 있는가 = 워커 사망 신호) |
| 매 확인 | CS 문의 유입 (카카오 채널·부재중 전화 포함) |
| 1시간 | 첫 실주문이 결제 → 처리 → 알림 → 수령까지 끝까지 갔는가 (사람이 눈으로 1건 추적) |
| 1시간 | 알림톡이 실제로 도착했는가 (스팸 처리·미도달 확인) |
| 3시간 | DB 커넥션 풀 사용률 (`connectionLimit: 10`. 외부 API 지연이 겹치면 전체 API 정지) |
| 6시간 | S3/KMS 오류 0건 |
| 12시간 | 자동 환불 발생 건과 사유 |
| 24시간 | **정기결제 스캔이 03:00에 발화했는가** (조용히 안 도는 것이 이 시스템의 알려진 실패 모드) |
| 24시간 | `[영상편지]` 사후 공개 검수 대기 건의 경과 시간 |
| 24시간 | 실주문 완료율·환불율 집계 |
| 24시간 | **fix 건수 집계** - 5건을 넘겼으면 개별 패치를 멈추고 공통 원인 회고 (05 문서 운영 원칙 3) |

### 즉시 중단 판단 기준
아래 중 하나라도 발생하면 신규 주문 접수를 멈추고 원인을 규명한다.
- [ ] 결제는 됐는데 처리가 시작되지 않는 건이 2건 이상
- [ ] 이중청구 1건이라도 확인
- [ ] `[영상편지]` 사후 전달 오류 1건이라도 발생 (OPERATIONS 5-4, 최고 심각도)
- [ ] 자동 환불이 동작하지 않는 상태에서 AI 실패가 누적
