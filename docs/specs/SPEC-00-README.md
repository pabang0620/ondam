> 작성일: 2026-08-21. `docs/PRD.md`(v1.0)와 `docs/strategy/`(사업 전략)의 사이를 메우는 기능 단위 세부 기획이다.
> 우선순위 근거: PRD 커버리지 실측 결과, PRD는 기능 목록·라우트·DB 스키마까지만 정의하고 동작 정책·예외 처리·화면 상세가 공백이었다.

## 문서 우선순위와 지위

- **충돌 시 우선순위: SPEC > strategy > PRD.** PRD v1.0(2026-04)은 전략 수립(2026-08) 이전 문서다. SPEC이 PRD와 다르게 정한 항목은 이 문서 세트가 정본이며, 각 SPEC 상단에 "PRD 대비 변경" 절로 명시한다.
- 코딩 AI에게는 해당 SPEC 전문 + `06-dev-backlog.md`의 태스크 항목 + `ondam/.claude/CLAUDE.md`를 함께 주입한다.

## 기획 변경 통제 원칙 (최상위 규칙)

**기획의 최종 결정권자는 사용자(기획 오너)다.** 아래 표에서 PRD의 기존 결정을 변경하는 항목은 사용자가 확정하기 전까지 `제안` 상태이며, `제안` 상태인 항목은 **구현에 착수하지 않는다** (관련 DEV 태스크 보류). 사용자가 채택/기각을 정하면 이 표의 상태를 갱신하고, 기각 시 해당 SPEC을 사용자 의도대로 수정한다. PRD에 없던 공백을 채운 항목(신설)은 리서치 근거 기반의 초안이며, 이 역시 사용자 의도에 따라 언제든 변경될 수 있다.
