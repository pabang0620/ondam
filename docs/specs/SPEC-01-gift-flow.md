# SPEC-01. 선물하기 (자녀 결제 → 부모 수행)

## PRD 대비 변경
PRD에는 선물·타인 결제 개념이 없고 `payments.user_id = 콘텐츠 소유자` 단일 전제다. 본 SPEC은 "결제자 ≠ 수행자(소유자)" 모델을 신설한다. 전략 근거: 실구매자는 4050 자녀 가설 (strategy/02 결정 3, Vaice 주 고객층 실증).

## 1. 대상 상품
- 1차: **AI 사진관 세트**, **마지막 영상 편지 (전 티어)**
- 제외: 펫 아카이브 구독(구독은 본인 결제만), 추모관(비상품)

## 2. 역할 정의
| 역할 | 설명 | 계정 필요 여부 |
|---|---|---|
| 구매자(giver) | 결제하는 자녀. 진행 상황을 조회함 | 회원 필수 |
| 수행자(recipient) | 사진 업로드·음성 녹음을 하는 부모. 콘텐츠 소유자 | **계정 불필요** (일회성 토큰 링크) |

소유권 원칙: 콘텐츠(사진·음성·영상)의 소유자는 수행자다. 구매자는 결과물 열람 권한을 수행자가 허용한 범위에서만 갖는다 (기본값: 사진관은 공유됨, 영상 편지는 **내용 비공개**, 완료 사실만 통지).

## 3. 사용자 플로우

### 3-1. 구매 (자녀)
```
상품 페이지 → [선물하기] 선택 → 받는 분 정보 입력(이름·휴대폰) →
결제(토스) → 선물 링크 생성 → [카카오톡으로 보내기 / 문자로 보내기 / 링크 복사]
```
- 받는 분 휴대폰 번호는 링크 본인 확인용(4-3)으로 사용
- 결제 완료 화면에 "부모님이 하실 일" 안내 미리보기 제공 (자녀가 전화로 설명할 수 있게)

### 3-2. 수행 (부모, 무계정)
```
링크 클릭 → 받는 분 확인(휴대폰 뒤 4자리 입력) → 안내 1화면("따님/아드님 ○○님이 선물을 보냈어요") →
[사진관] 사진 올리기 → 완료
[영상 편지] 동의 → 사진 올리기 → 음성 녹음(가이드 문장 낭독) → 수신인 확인 → 완료
```
- 한 화면 한 행동. 뒤로 가도 진행 상태 저장 (토큰 기준 임시 저장)
- 영상 편지의 수신인 목록은 구매 시 자녀가 초안 입력 가능하되, **최종 확정은 수행자(부모)가 한다** (본인의 전달 의사가 원칙이므로)
- 동의(음성 클론·AI 영상)는 반드시 수행자 본인이 화면에서 직접 체크 (구매자가 대리 동의 불가)

### 3-3. 완료 후
- 처리 완료 시: 수행자에게 결과 통지(알림톡/SMS), 구매자에게 "완료되었습니다" 통지 (내용 미포함)
- 미수행 리마인드: 링크 발송 후 미진입·미완료 상태가 지속되면 수행자에게 최대 2회, 구매자에게 1회 통지 (횟수 고정, 시점은 운영 설정값)

## 4. 정책·엣지 케이스

| 케이스 | 정책 |
|---|---|
| 4-1 토큰 만료 | 발급 후 90일. 만료 시 구매자가 마이페이지에서 재발급(기존 토큰 무효화) |
| 4-2 토큰 유출 | 서명 토큰 + 휴대폰 뒤 4자리 확인 + 오입력 5회 잠금(구매자에게 통지) |
| 4-3 수행자가 이미 회원 | 링크 진입 시 "기존 계정에 연결하기" 선택지 제공. 연결하면 콘텐츠가 그 계정 소유로 |
| 4-4 수행 전 환불 요청 | 수행자가 링크 진입 전이면 전액 환불 가능 (SPEC-02 준용) |
| 4-5 수행자 거부 | 수행 화면에 "정중히 거절하기" 제공 → 구매자 통지 + 전액 환불. 죽음 준비 상품 특성상 강요 금지 장치 필수 |
| 4-6 수행자 사망·수행 불능 | 미수행 상태 지속 시 자동 환불하지 않고 구매자에게 선택지 통지(환불 / 기한 연장) |
| 4-7 구매자·수행자 분쟁 | 콘텐츠 소유권은 수행자. 구매자의 삭제 요구는 수행자 동의 없이는 불가 (약관 명시) |

## 5. 데이터 모델 (신규, 기존 스키마 컨벤션 준수)

```
gift_orders
  id BIGINT AI PK, uuid CHAR(36) UNIQUE
  giver_user_id → users.id
  product_type ENUM('photo','will')  -- payments.order_type과 정합
  tier VARCHAR(20) NULL              -- 영상 편지 티어
  payment_id → payments.id
  recipient_name, recipient_phone(암호화)
  perform_token CHAR(64) UNIQUE      -- 서명 토큰 해시 저장
  token_expires_at DATETIME
  status ENUM('paid','link_sent','opened','in_progress','completed','declined','refunded','expired')
  recipient_user_id → users.id NULL  -- 4-3 계정 연결 시
  created_at, updated_at, deleted_at

gift_order_logs  -- 상태 전이 이력 (기존 *_logs 패턴)
```
- 완료 시 생성되는 `photo_orders`/`wills` 레코드의 소유자는 recipient (연결 계정 또는 임시 소유 후 계정 생성 유도)

## 6. API 초안 (응답 포맷 `{success, message, data}` 준수)

```
POST /api/gifts                     (requireAuth)  선물 주문 생성+결제 준비
GET  /api/gifts/mine                (requireAuth)  내가 보낸 선물 목록·상태
POST /api/gifts/:uuid/resend        (requireAuth)  링크 재발급·재전송
GET  /api/gifts/perform/:token      (무인증)       수행 화면 데이터 (뒤 4자리 검증 후)
POST /api/gifts/perform/:token/verify   휴대폰 뒤 4자리 검증 (5회 제한)
POST /api/gifts/perform/:token/...      수행 단계별 저장 (업로드·녹음·수신인·동의)
POST /api/gifts/perform/:token/decline  거절 (4-5)
```

## 7. 수용 기준 (구현 완료 판정)
1. 자녀 계정 결제 → 부모 무계정 수행 → 제작 완료 → 양측 통지까지 E2E 성공
2. 토큰 만료·재발급·오입력 잠금·거절·환불 각 케이스 동작
3. 동의 체크가 수행자 화면에서만 가능하고 `user_consents`(또는 무계정용 동의 기록)에 IP/UA와 함께 기록
4. 영상 편지 내용이 구매자에게 노출되지 않음 (API 레벨 차단 확인)
