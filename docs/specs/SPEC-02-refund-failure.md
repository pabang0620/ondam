# SPEC-02. 환불·취소 정책 및 AI 실패 처리

## PRD 대비 변경
PRD에는 환불 정책 텍스트가 없다 (`refunded_at`/`refund_amount` 컬럼과 "재처리 1회 무료" 한 줄만 존재). 본 SPEC이 상품 유형별 정책을 신설한다. 최종 문구는 법률 검토(strategy/07 체크리스트 6번, 전자상거래법 청약철회) 후 확정한다.

## 1. 환불 정책 (상품별)

| 상품 | 처리 착수 전 | 처리 착수 후 | 결과물 수령 후 |
|---|---|---|---|
| AI 사진관 | 전액 환불 (버튼 셀프 취소) | 환불 불가 원칙, 단 품질 불만 시 무료 재처리 1회 → 재처리도 불만이면 전액 환불 | 좌동 |
| 영상 편지 | 전액 환불 | AI 생성 착수 후 환불 불가 원칙, 품질 불만 시 재생성 1회 → 불만 시 전액 환불 | 전달 예약 전이면 좌동. 사후 전달 완료 후에는 환불 불가 |
| 선물 주문 | 수행자 링크 미진입 시 전액 (SPEC-01 4-4) | 수행 시작 후에는 위 각 상품 기준 준용 | 좌동 |
| 펫 구독 | 첫 결제 후 콘텐츠(초상화) 미사용 시 당월 전액 | 사용 시 당월 환불 불가, 해지는 익월부터 (자동갱신 중단) | - |

- "처리 착수" 정의: BullMQ 작업이 `ai_jobs`에서 processing 상태로 전이된 시점. 그 전(대기열)은 착수 전으로 본다.
- 관대한 환불 원칙: 시니어 타겟에서 환불 분쟁 1건의 평판 비용이 환불액보다 크다. 경계 사례는 환불 쪽으로 처리한다 (관리자 재량 환불 권한: SPEC-06).

## 2. AI 처리 실패 자동 처리 (DEV-08 상세)

### 상태 흐름
```
ai_jobs: queued → processing → (성공) completed
                              → (실패) retrying(자동 N회) → failed(최종)
failed(최종) 도달 시:
  1) 주문 상태 'failed' 기록 (photo_order_logs / will_status_logs)
  2) 토스 결제 자동 취소 (전액)
  3) 사용자 통지: "죄송합니다. 처리에 실패해 결제를 취소해 드렸어요. 다시 시도해 보시겠어요?"
  4) 관리자 대시보드 실패 큐에 노출 (SPEC-06)
```
- 자동 재시도 횟수는 작업 유형별 설정값 (기본: 사진 2회, 영상 1회. 영상은 벤더 과금이 크므로 보수적으로)
- **중복 환불 가드 필수**: 환불 API 호출 전 `payments.status` 확인 + 멱등키 사용
- 부분 실패(사진관 세트 4종 중 1종 실패): 성공분은 제공하고, 실패 항목은 재시도 → 최종 실패 시 **전액** 환불 (부분 환불은 계산 분쟁 소지가 커서 도입하지 않음. 결과물은 그대로 가져가게 둔다)

### 품질 불만 재처리 (사용자 트리거)
- 결과물 화면에 "마음에 안 들어요" 버튼 → 사유 선택(닮지 않음/훼손/기타) → 무료 재처리 1회 자동 실행
- 재처리 후에도 불만: "환불 요청" 버튼 → 관리자 승인 환불 (자동 아님, 어뷰징 방지)
- 재처리·환불 요청 이력은 `reprocess_count`와 로그 테이블로 추적

## 3. 결제 취소·해지 UX

- 마이페이지 주문 내역에서 상태별 버튼 노출: `대기 중 → [주문 취소]` / `처리 중 → (버튼 없음, 안내문)` / `완료 → [재처리 요청]`
- 구독 해지: 마이페이지에서 셀프 해지, 즉시 해지가 아니라 만료일까지 이용 유지. 해지 사유 1문항(선택) 수집
- 전화 문의 안내를 취소·환불 화면마다 병기 (5060 신뢰 장치)

## 4. 수용 기준
1. 상태별 셀프 취소/재처리/환불 요청 버튼이 정책 표와 일치하게 노출
2. 최종 실패 시 환불·통지·로그 3종 자동 수행, 중복 환불 0건 (멱등 테스트)
3. 부분 실패 시나리오에서 성공분 제공 + 전액 환불 동작
4. 약관·구매 화면에 환불 규정 고지 (법률 검토 반영 후 문구 확정)
