## 해소할 충돌
- PRD: 반려동물 추모 페이지 `/memorial/:slug` **공개** 방식만 정의 (`pets.memorial_slug` + `is_public`). 방명록은 예시 그림에만 있고 기능·테이블 미정의.
- 로컬 `.claude/CLAUDE.md`: "고인 추모관은 유가족 전용, 접근 코드 검증" 방식 언급.
- 두 문서가 다른 대상을 다른 모델로 말하고 있어 본 SPEC이 이원화로 확정한다.

> **오너 확정 2026-08-21**: 아래 이원화 모델(사람=비공개 / 펫=공개선택)을 채택. DEV-16 착수 가능. 방금 추가한 `pets.memorial_access_code` 컬럼의 정책은 "사람 추모 공간은 항상 비공개, 펫은 소유자 공개선택"으로 확정.

> ## [2026-08-22] "추모관"이 무엇인지에 대한 정본 정의
>
> 문서마다 추모관이 다른 것을 가리켜 구현자가 혼란할 수 있어 여기서 확정한다. **이 절이 정본이다.**
>
> | | 사람(고인) | 반려동물 |
> |---|---|---|
> | 실체 | **독립 엔티티가 아니다.** 수신인별 토큰으로 여는 **열람 화면**(`/watch/:token`)이 곧 사람의 추모 공간이다 | **독립 엔티티**. `pets` 레코드에 딸린 공개 페이지(`/memorial/:slug`) |
> | 데이터 모델 | 별도 테이블 없음. `wills` + `will_beneficiaries`의 토큰으로 접근 | `pets.memorial_slug`, `pets.memorial_access_code`, `pets.is_public`(마이그레이션 b) |
> | 접근 | 수신인 토큰 + 본인 확인. 공개 옵션 없음 | 공개(is_public) 또는 접근코드 |
>
> **따라서**: `pets.memorial_access_code`와 `is_public`은 **펫 전용 컬럼**이다. 사람용 추모관 테이블을 새로 만들지 마라.
> `strategy/03` 1절 ④의 "추모관 = 구매자의 보관·열람 공간"과 `.claude/CLAUDE.md`의 "`/api/memorial/:code` 유가족 전용" 서술은 이 정의로 읽는다(둘 다 펫 추모 페이지 + 사람 열람 화면을 뭉뚱그린 표현이었다).

## 1. 확정 모델: 대상별 이원화

| | 사람(고인) 추모 공간 | 반려동물 추모 페이지 |
|---|---|---|
| 성격 | 영상 편지·사진관 결과물의 **비공개 보관·열람 공간** | 기억 아카이브의 **공개 선택형 전시 페이지** |
| 기본 공개 상태 | **항상 비공개** (공개 옵션 없음) | 비공개 기본, 소유자가 공개 전환 가능 |
| 접근 방식 | 접근 코드(고엔트로피 코드) + 수신인별 서명 토큰(`will_beneficiaries.video_token`) | 공개 시 `memorial_slug` URL, 비공개 시 소유자만 |
| 검색엔진 노출 | 차단 (noindex + 로봇 차단) | 공개 페이지만 허용 |
| 방명록 | 없음 (유가족 간 비공개 공간이므로 도입하지 않음) | **도입** (2절) |

- 사람 추모 공간에 공개 옵션을 두지 않는 이유: 고인 데이터의 공개는 잊힐 권리·유족 간 분쟁 리스크가 크고(strategy/07 R3·R9), 온담 포지셔닝은 "전시"가 아니라 "전달·보관"이다.
- 반려동물은 반대로 공개·공유가 애도 문화(SNS 추모)와 맞고 바이럴 유입 채널이 된다.

## 2. 반려동물 방명록 (신규 기능 확정)

PRD 예시 그림에만 있던 방명록을 정식 기능으로 확정한다.

- 공개 추모 페이지에서 비회원도 작성 가능: 이름(닉네임) + 짧은 글 + 헌화 이모지 선택
- 스팸 방어: 페이지당 작성 속도 제한 + 금칙어 필터 + 소유자 삭제 권한 + 신고 버튼(관리자 큐로, SPEC-06)
- 데이터: `pet_memorial_entries` 신규 테이블 (id/uuid, pet_id, author_name, body, flower_type, author_ip 해시, status ENUM('visible','hidden','reported'), created_at, deleted_at)
- 작성 시 소유자에게 인앱 알림 (SPEC-04 매트릭스 등재)

## 3. 화면 정의

### 사람 추모 공간 (수신인 시점, `/watch/:token` 확장)
1. 진입: 수신인별 토큰 링크 → 본인 확인(휴대폰 뒤 4자리) → 열람
2. 구성: 고인 인사말 화면(이름·사진) → 영상 재생 → 함께 보관된 사진(사진관 결과물 중 고인이 공개 지정한 것) → "다른 가족과 함께 보기" 안내(각자 링크로만, 링크 전달 금지 문구)
3. 만료·재발송 UX는 SPEC-05가 정본

### 반려동물 추모 페이지 (`/memorial/:slug`)
- PRD 예시 구성(소개글·갤러리·영상·기일) 유지 + 방명록 섹션 + [공유] 버튼(공개 상태일 때만)
- 소유자 편집 모드: 공개/비공개 토글, 방명록 관리(숨김·삭제), 기일 알림 설정

## 4. 수용 기준
1. 사람 추모 공간이 어떤 경로로도 비로그인·무토큰 접근 불가 (직접 URL 추측 포함)
2. 펫 페이지 공개/비공개 전환이 즉시 반영되고 비공개 시 slug 접근이 404가 아닌 안내 화면
3. 방명록 작성·신고·소유자 삭제 E2E + 속도 제한 동작
4. 사람 공간 전 페이지 noindex 확인
