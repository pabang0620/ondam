# SPEC-04. 알림 매트릭스 (이벤트 × 채널 × 템플릿)

## PRD 대비 변경
PRD는 채널(SMS·이메일·인앱)만 나열하고 발송 정책이 없으며, **카카오 알림톡이 문서 전체에 미등장**한다. 본 SPEC은 알림톡을 1순위 채널로 도입하고 이벤트별 매트릭스를 확정한다.

## 1. 채널 전략

| 채널 | 용도 | 비고 |
|---|---|---|
| **알림톡 (1순위)** | 결제·처리완료·전달 등 트랜잭션 통지 전반 | 5060 도달률 최고, SMS 대비 저비용. 발신프로필·템플릿 사전 심사 필요 |
| SMS (폴백) | 알림톡 실패·미수신 시 자동 폴백, 비회원(수신인·선물 수행자) 통지 | 실패 폴백은 발송 벤더 기능 활용 |
| 인앱 (`notifications`) | 전 이벤트 병행 기록 (마이페이지 알림함) | 기구현 구조 유지 |
| 이메일 | 영수증·약관 변경 등 기록성 통지만 | 5060 도달률 낮음, 주 채널로 쓰지 않음 |
| 푸시 | **도입하지 않음** (웹앱 단계에서 불필요, `via_push` 설정만 예약) | - |

- 발송 실패가 주문 흐름을 막지 않는다 (비차단, `notificationWorker` 경유)
- `notifications.sent_via` ENUM에 `'alimtalk'` 추가 필요

## 3. 수신 동의·거부 정책

- **트랜잭션 통지**(결제·처리·전달)는 수신 거부 대상이 아니다 (서비스 이행에 필수, 정보통신망법상 광고가 아님)
- **정서적 알림**(펫 기일, 생일 관련)은 `user_notification_settings`로 개별 on/off. 기본값 on이되 첫 발송에 해제 안내 포함
- 마케팅 발송은 본 SPEC 범위 외 (별도 마케팅 동의 `user_consents.marketing` 있는 회원만, 도입 시 별도 기획)

## 4. 발송 벤더·구현 지침
- 알림톡+SMS 폴백을 한 API로 처리하는 국내 벤더(예: 알리고·솔라피·NHN Cloud 계열) 중 선택. 선정 기준: 폴백 자동화, 템플릿 관리 API, 건당 단가
- 템플릿은 코드에 하드코딩하지 않고 템플릿 ID 매핑 테이블(설정 파일)로 관리 (알림톡 심사로 문구 변경이 느리므로 변수부 최대화)
- 발송 이력은 `notifications`에 채널·성공여부·벤더 메시지 ID 기록 (CS 추적용)

## 5. 민감 발송 문구 원칙 (사후 열람 링크)
- 죽음을 직접 언급하는 단어 최소화. 예: "고(故) ○○○님이 ○○님께 남긴 영상이 도착했습니다. 마음의 준비가 되실 때 열어보세요."
- 열람 강요 금지: 만료 임박 통지는 1회로 제한, "연장 요청" 경로 안내 포함 (SPEC-05)
- 심야 발송 금지 (발송 가능 시간대 운영 설정)

## 수용 기준
1. 매트릭스의 전 이벤트가 지정 채널로 발송되고 실패 시 SMS 폴백 동작
2. 발송 실패가 주문·전달 트랜잭션을 롤백시키지 않음
3. 정서적 알림 해제 시 미발송 확인
4. `notifications`에 벤더 메시지 ID까지 기록되어 건별 추적 가능
