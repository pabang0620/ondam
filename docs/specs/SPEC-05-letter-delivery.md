# SPEC-05. 영상 편지 열람·만료·재발송 + 보관 정책

## PRD 대비 변경 (중요 결정 2건)

### 결정 A: 보관 구독(월 1,900원) 폐지 [확정 2026-08-21 오너 채택]
- PRD: 유언장 생성 후 "KMS 보관 월 1,900원 구독, 해지 시 30일 삭제 예고" 락인 모델
- **변경: 폐지. 보관비는 단건 가격(티어)에 내재화한다.**
- 근거:
  1. "구독을 끊으면 유언 영상이 삭제된다"는 구조는 브랜드 신뢰 원칙("삭제는 본인 의사로만")과 정면 충돌하고, 시니어 타겟에서 "협박형 과금"으로 읽힐 CS·평판 리스크가 크다
  2. 저가 구독의 지속성 실패는 HereAfter(월 $3.99~7.99 → 폐업)로 실증됨 (strategy/01)
  3. 월 1,900원 매출보다 티어 상향(스탠다드·프리미엄)의 객단가 기여가 크다
- 보관 기간 약속: 베이직/스탠다드 "전달 완료 후 N년 보관", 프리미엄 "영구 보관(서비스 존속 기간)" 형태로 티어 차등. N값과 문구는 법률 검토(보존 의무·소비자 고지)와 스토리지 원가 실측 후 확정
- 서비스 종료 시 처리(데이터 반출 제공 등) 약관 명시 필수: 이 카테고리 최대 신뢰 질문("회사가 망하면 내 영상은?")에 대한 답을 선제 게시

### 결정 B: 열람 화면을 "핵심 순간"으로 승격
PRD는 `/watch/:token` "비회원, 암호화 영상 재생" 한 줄뿐이다. 수신인의 열람 순간이 이 서비스의 존재 이유이자 바이럴 원점이므로 아래와 같이 상세 정의한다.

## 1. 전달 플로우 전체 (기존 구조 승계 + 보강)

```
[유가족] /release/:token 진입 → 사망증명서 업로드 → 접수 통지
   ↓
[관리자] 검토 (SPEC-06 검수 화면) → 승인 / 반려(사유)
   ↓ 승인
[시스템] 수신인별 개별 링크 생성(will_beneficiaries.video_token, 90일)
   → 알림톡/SMS 발송 (SPEC-04 5절 문구 원칙)
   ↓
[수신인] /watch/:token 열람
```
- 반려 시: 요청 유가족에게 사유와 재요청 방법 통지 (재요청 횟수 제한 3회, 초과 시 전화 CS 전환)
- 승인 전 이중 확인: 관리자 승인 버튼에 고인 이름·수신인 수 요약 확인 단계 (오전달 방지, strategy/07 법률 4번)

## 2. 열람 화면 `/watch/:token` 상세

### 진입·본인 확인
1. 링크 진입 → 수신인 이름 표시 "○○님께 도착한 영상 편지입니다" → 휴대폰 뒤 4자리 확인 (오입력 5회 잠금 → CS 안내)
2. 잠금·비정상 접근은 `audit_logs` 기록

### 열람 경험 (감정 설계)
1. **준비 화면**: 자동 재생하지 않는다. "마음의 준비가 되시면 눌러주세요" 버튼 → 재생. (감정적 충격 배려, 공공장소에서 열었을 가능성)
2. 재생 화면: 고인 이름·사진, 영상 플레이어(대형 컨트롤, 어르신 UX 규칙), 다시 보기 무제한
3. 재생 후: 개별 메시지 텍스트(있는 경우), 함께 전달된 사진, "다른 가족들도 각자의 영상을 받았습니다" 안내
4. **다운로드: 제공한다.** 90일 후 링크가 만료돼도 유족이 영상을 잃지 않도록 원본 다운로드 버튼 제공 (워터마크 없음. "우리 소유가 아니라 유족의 것"이라는 원칙이자 신뢰 장치)
5. 하단: 온담 소개 1줄 + "나도 남기고 싶다면" 링크 (열람자가 다음 고객이 되는 유일한 지점. 과하지 않게 1개만)

### 열람 추적
- `video_watched_at`, `watch_count` 기록 (기존 컬럼). 미열람 수신인은 만료 7일 전 1회 리마인드 (SPEC-04)

## 3. 만료·재발송 정책

| 케이스 | 정책 |
|---|---|
| 90일 내 미열람 만료 | 링크 만료 화면에 "연장 요청" 버튼 → 요청 시 신규 토큰 재발급(+90일). 무제한 허용하되 재발급마다 구토큰 무효화·로그 기록 |
| 수신인 연락처 변경·오류 | 사후 공개를 요청했던 유가족이 연락처 정정 요청 → 관리자 확인 후 재발송 (본인 확인 절차 포함) |
| 수신인 사망·수신 거부 | 해당 수신인 전달 중단 처리 (관리자). 다른 수신인에게 재배정하지 않음 (고인 의사 존중) |
| 열람 전 유가족 간 분쟁 신고 | 전달 일시 중지 상태 신설 → 관리자 판단·법률 자문 후 재개/중단 |

## 4. 티어 반영 (strategy/03 연계)
- 스탠다드 수신인 3명 개별 메시지: 기존 `will_beneficiaries` 1~5명 구조 그대로 활용 (베이직=1명, 스탠다드=3명, 프리미엄=무제한이 아닌 상한 10명으로 실무 확정. "무제한"은 발송·검수 비용 통제 불가)
- 프리미엄 "기일 자동 재전달": 매년 기일에 수신인에게 "다시 보기" 링크 재발송 (BullMQ repeatable). 수신인이 해제 가능
- strategy/03의 프리미엄 정의 중 "수신인 무제한"은 본 SPEC으로 "최대 10명"으로 정정한다

## 수용 기준
1. 요청 → 승인 → 발송 → 본인 확인 → 열람 → 다운로드 E2E
2. 만료 → 연장 요청 → 재발급 → 재열람 동작, 구토큰 무효 확인
3. 미열람 리마인드 1회만 발송되는지 확인
4. 보관 구독 관련 코드·화면·과금이 제거되고(`will_storage` 플랜 비활성), 기존 PRD식 "해지 시 삭제" 로직이 어디에도 없음
