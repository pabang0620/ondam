# SPEC-06. 관리자 콘솔: 권한 매트릭스 + 운영 화면

## PRD 대비 변경
PRD는 관리자 화면 4개의 이름과 `admin_users.role` ENUM 3종(super_admin / content_moderator / payment_specialist)만 정의했다. 본 SPEC이 역할별 권한 매트릭스와 운영 화면 구성을 확정한다. 초기 운영 인력이 1~2명임을 전제로, 화면은 최소 세트로 시작한다.

## 1. 권한 매트릭스

| 기능 | super_admin | content_moderator | payment_specialist |
|---|---|---|---|
| 대시보드 조회 | O | O | O |
| 사후 공개 검수 (승인/반려) | O | O | - |
| 신고·방명록 모더레이션 | O | O | - |
| 주문 조회 | O | O | O |
| 주문 상태 수동 변경·AI 재시도 | O | - | O |
| 재량 환불 실행 | O | - | O |
| 구독 관리 (해지·플랜 변경) | O | - | O |
| 회원 조회 | O | O(콘텐츠 관련만) | O(결제 관련만) |
| 회원 제한·정지 | O | - | - |
| 관리자 계정 관리 | O | - | - |
| audit_logs 열람 | O | - | - |

- 모든 쓰기 행위는 `audit_logs`에 기록 (행위자·대상·전후 값·사유). 기존 컨벤션 유지
- `permissions JSON` 컬럼은 위 매트릭스의 예외 부여용으로만 사용 (기본은 role 기준)
- 사후 공개 승인은 어떤 role이든 **단독 즉시 승인 불가 케이스**를 둔다: 요청자와 회원 정보 불일치 등 시스템 경고 플래그가 붙은 건은 super_admin만 승인 가능

## 2. 운영 화면 (기존 4개 + 보강)

### `/admin` 대시보드
- 오늘 지표: 신규 주문·매출·처리 중·**실패 건수(빨강)**·검수 대기 건수
- 바로가기: 실패 큐, 검수 대기, 환불 요청 대기
- KPI 위젯: North Star(전달 예약 영상 수), 업셀 전환율, 선물 동선 비중 (strategy/04 지표를 여기서 본다)

### `/admin/release` 사후 공개 검수 (가장 중요한 화면)
- 대기 목록: 요청일·고인명·요청자·수신인 수·경고 플래그
- 상세: 사망증명서 뷰어(KMS 복호화 열람, 열람 자체가 audit_logs 기록), 회원 정보 대조 패널(이름·생년 일치 여부 자동 표시), 요청자 관계 정보
- 액션: 승인(요약 확인 단계 포함, SPEC-05 1절) / 반려(사유 필수, 정형 사유 + 자유 입력) / 보류(전화 확인 필요 메모)
- SLA 표시: 접수 후 경과 시간 표시 (유족이 기다리는 화면임을 상기)

### `/admin/orders` 주문·작업 관리
- 필터: 상품·상태·기간. **실패 큐 탭 분리** (ai_jobs 최종 실패 + 자동환불 여부 표시)
- 건별 액션: AI 작업 수동 재시도, 상태 수동 전이(사유 필수), 재량 환불(금액 확인 단계), 벤더 응답 원문 열람(디버깅용)
- 선물 주문 탭: SPEC-01 상태별 조회, 링크 재발급, 분쟁 메모

### `/admin/users` 회원 관리
- 조회·검색, 회원별 주문·구독·동의 이력, 제한/정지(사유 필수)
- 탈퇴 요청·데이터 삭제 요청 처리 큐 (SPEC-07 연계)

### `/admin/moderation` (신규, 경량)
- 펫 방명록 신고 큐 (SPEC-03): 신고 사유·본문 확인 → 숨김/복구/작성 차단

## 3. 운영 수칙 (화면에 내장할 가드)
- 환불·정지·승인 등 파괴적 액션은 전부 2단계 확인 + 사유 입력 강제
- 관리자 로그인: 별도 엔드포인트(기구현) + 실패 5회 잠금. 초기엔 IP 제한(허용 목록) 권장
- 관리자용 API는 전부 `requireAuth + requireAdmin` 2층 (기존 컨벤션) + role 검사 미들웨어 추가

## 수용 기준
1. role별 계정으로 로그인 시 매트릭스와 정확히 일치하는 메뉴·액션만 노출되고, API 레벨에서도 차단됨 (화면 숨김만으로는 불충분)
2. 검수 화면에서 증빙 열람·승인·반려 전 과정이 audit_logs에 남음
3. 실패 큐에서 수동 재시도·재량 환불이 동작하고 중복 환불 가드 유지
4. 경고 플래그 건이 content_moderator로 승인 불가함 확인
