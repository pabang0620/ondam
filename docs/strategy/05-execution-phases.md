# 05. 실행 로드맵: Phase 게이트

> 일정·기간 견적은 두지 않는다. 각 Phase는 **완료 판정 기준(게이트)** 충족 시 다음으로 넘어간다.
> 개발 태스크 상세는 [06-dev-backlog.md](06-dev-backlog.md)의 태스크 ID 참조.
>
> **2026-08-21 현행화**: 전체 코드 감사([../review/2026-08-21-full-audit.md](../review/2026-08-21-full-audit.md))에서 배포 차단 결함(BLOCKER 6·HIGH 8)이 확인됐다. 현재 코드는 가입·결제·핵심기능이 실제로 동작하지 않는 상태다. 따라서 아래 Phase 1보다 앞에 **Phase 0(결함 개선)**을 신설한다. Phase 0을 통과하기 전에는 어떤 출시도 없다.

## Phase 0: 결함 개선 (신설, 최우선 - 이것 없이는 출시 불가)

목표: 감사에서 드러난 "동작하지 않는 상태"를 "돈 받아도 되는 상태"로 되돌린다. 상세 실행은 [../review/remediation-plan.md](../review/remediation-plan.md), 재발 방지 규약은 [../guidelines/DEVELOPMENT_GUIDELINES.md](../guidelines/DEVELOPMENT_GUIDELINES.md).

| 작업 | 태스크 ID | 게이트 기준 |
|---|---|---|
| 스키마·enums 재동기화 | DEV-22 | 마이그레이션 적용(사용자 실행) + 코드 반영. 가입·주문·펫초상화·추모관·구독취소 실제 성공 |
| 결제 금액·소유권 서버검증 | DEV-23 | 금액 조작·타인 targetId 차단, 정상 결제 통과 |
| 프론트 mock 폴백 제거 | DEV-24 | 실패가 실패로 보임(성공 위장 0건). 이후 수정의 검증 가능해짐 |
| 토스 결제 왕복 실구현 | DEV-25 | 사진관·유언편지 실결제 E2E |
| 결제 크론·retry·알림 ENUM | DEV-26 | 정기결제 실제 발화, 재시도 성공, 유가족 알림 발송 |
| 인증·세션·보안·잔여 HIGH | DEV-27~29 | 공개페이지 접근·세션유지·OAuth state·rate limit 등 |

**Phase 0 종료 게이트**: BLOCKER 6 + HIGH 8 해소 + code-reviewer APPROVED + 핵심 플로우 E2E 통과. 이 게이트 전에는 Phase 2(출시)로 못 간다.

> 아래 Phase 1~4는 결함이 없다는 전제의 원래 로드맵이다. Phase 0 통과 후 유효하다. 일부 항목(DEV-03 스키마 정리, DEV-05 명칭 등)은 Phase 0에 흡수됐다.

## Phase 1: 제품 리스크 해소 (출시 전 필수)

목표: "돈을 받아도 되는 상태"를 만든다. 기술·결제·데이터 3대 리스크 제거.

| 작업 | 태스크 ID | 게이트 기준 |
|---|---|---|
| 립싱크 벤더 1곳 실검증 | DEV-01 | 실제 벤더 API로 사진+음성 → 영상 E2E 1건 성공. 건당 원가·처리 시간·한국어 품질 기록 |
| AI 원가 실측 | DEV-02 | 사진관 세트·영상 편지 1건의 원가표 산출 → 03 문서 가격 확정 |
| 스키마 중복 정리 | DEV-03 | `subscription_payment_logs` 중복 정의 해소, 스키마 파일 단일 정본화 |
| 결제 실거래 검증 | DEV-04 | 토스 실결제·취소·웹훅 E2E 통과 |
| 명칭 변경 반영 | DEV-05 | "유언장" → "영상 편지" 로 사용자 노출 문구 전면 교체 |
| 법률·약관 정비 | (외부) | 약관에 법적 효력 없음·동의·삭제권 명시 (07 문서 체크리스트) |

**Phase 1 종료 게이트**: 위 6개 전부 충족. 단, DEV-01(립싱크)은 사진관 출시를 막지 않는다 → 미완이어도 Phase 2 진입 가능, Phase 3 진입만 막는다.

## Phase 2: 사진관 단독 출시 + 수요 실측

목표: 립싱크 완성을 기다리지 않고 시장 검증을 시작한다 (StoryFile류 "완성까지 자금 소진" 패턴 회피).

| 작업 | 태스크 ID | 내용 |
|---|---|---|
| 사진관 구매 플로우 완결 | DEV-06 | 업로드 → 결제 → AI 처리 → 알림 → 결과물 수령까지 무개입 E2E |
| 처리 완료 알림(알림톡/SMS) | DEV-07 | 비동기 처리 완료를 문자로 통지 (5060 UX 필수) |
| 실패 자동 환불 | DEV-08 | AI 처리 실패 시 자동 환불 + 안내 |
| 공유 기능 | DEV-09 | 결과물 카카오톡 공유·가족 단톡 전송 동선 |
| 랜딩 정비 | DEV-13 | 가격 공개·전후 비교·신뢰 장치 반영 (03 문서 4절) |
| 소액 광고 테스트 | (운영) | CAC 실측 (04 문서 3절 판정식) |

**Phase 2 종료 게이트**:
- 실주문 처리 무사고 운영이 확인되고 (결제 → 수령 완료율, 환불율 지표 안정)
- CAC 판정식 결과가 나오고 (확장 가능 or 미끼상품 규정)
- DEV-01(립싱크 벤더 확정)이 완료된 상태

## Phase 3: 영상 편지 출시 + 확장

목표: 코어 상품으로 마진을 만들고, 선물 동선·펫 축을 연다.

| 작업 | 태스크 ID | 내용 |
|---|---|---|
| 영상 편지 티어 상품화 | DEV-11 | 확정 벤더로 베이직/스탠다드/프리미엄 (03 문서 티어) |
| 자녀 선물 동선 | DEV-10 | 자녀 결제 → 부모 링크 수행 플로우 (03 문서 B동선) |
| 사후 전달 플로우 검수 강화 | DEV-12 | 사망증명서 업로드 → 관리자 승인 → 수신인 전달 E2E + 관리자 화면 완비 |
| 펫 아카이브 구독 오픈 | DEV-14 | 무료/구독/단품 구조 + 정기결제 검증 |
| 시즌 캠페인 | (운영) | 어버이날·명절 패키지 (선물 동선 완성 후) |
| 장묘업체 제휴 영업 | (운영) | 86곳 리스트업 → 쿠폰 제휴 제안 |

**Phase 3 종료 게이트**: 업셀 전환율·티어 분포·선물 동선 비중 지표가 수집되어 04 문서의 가설 4개가 판정됨.

## Phase 4 (조건부): 스케일

Phase 3 가설 판정 결과에 따라 선택한다. 미리 결정하지 않는다.
- 가설 1·2 성립(자녀 결제 + 업셀 작동) → D2C 광고 확대 + 시즌 집중
- 가설 4 성립(펫 제휴 전환) → 장묘 제휴 전국 확대, 펫 구독을 제2 코어로
- D2C 검증 후 → 중소 상조·장례식장 화이트라벨 영업 착수

## 운영 원칙

1. **게이트를 건너뛰지 않는다**: 특히 "립싱크 미검증 상태로 영상 편지 판매 개시"는 금지 (환불 대란·브랜드 손상 직결).
2. **결제·전달 등 고위험 하위시스템은 해당 Phase 전까지 placeholder 유지** (선제 구현 금지).
3. **fix 누적 감시**: 출시 후 하루 fix 5건 초과 시 개별 패치를 멈추고 공통 원인 회고.
4. 각 Phase 종료 시 이 문서와 06 백로그의 상태를 갱신한다.
